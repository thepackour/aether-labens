# Aether Labens

> *aether labens* — 라틴어로 "미끄러지는 에테르"

**Aether Labens**는 여러 플레이어가 하나의 거대한 맵을 함께 쓰는 실시간 슬라이딩 퍼즐 웹게임입니다.
플레이어는 방향만 고를 수 있고, 한번 움직이기 시작하면 무언가에 부딪힐 때까지 멈추지 않고 미끄러집니다.

무대는 우주처럼 보이지만 우리가 아는 우주는 아닌, 에테르로 가득 찬 **다른 차원**입니다.
떠다니는 블록과 결정체 사이를 미끄러지며 길을 찾는 것이 이 게임의 전부이자 핵심입니다.

> 🚧 기획 단계의 프로젝트입니다. 아래 내용 중 일부는 확정되지 않았고, 미정인 부분은 따로 표시해 두었습니다.

## 게임 소개

보드게임 *리코셰 로봇(Ricochet Robots)* 의 "벽에 닿을 때까지 미끄러지는 이동"을 바탕으로 한 퍼즐 게임입니다.
리코셰 로봇이 한 판의 보드 위에서 최소 수를 겨루는 게임이라면, Aether Labens는 그 규칙을 **끝없이 이어지는 공유 맵**으로 옮겼습니다.

- 모든 플레이어가 **같은 맵**에 있습니다. 다른 플레이어도 내 경로의 장애물이자 발판이 됩니다.
- 누군가 블록을 부수거나 옮기면 그 변화가 **모든 플레이어에게 실시간으로** 보입니다.
- 한 번의 이동은 짧지만, 어디서 멈출지를 계산하는 것이 퍼즐입니다.

## 핵심 규칙

1. 플레이어는 상·하·좌·우 중 한 방향을 고릅니다.
2. 고른 방향으로 **장애물에 부딪힐 때까지** 미끄러집니다. 중간에 멈출 수 없습니다.
3. 멈추는 조건은 다음과 같습니다.
   - 벽이나 블록에 부딪힘 → 바로 앞 칸에서 멈춤
   - 다른 플레이어에 부딪힘 → 그 플레이어 바로 앞 칸에서 멈춤
   - 거미줄처럼 "붙잡는" 칸에 들어감 → 그 칸 위에서 멈춤
4. 이동 중 지나간 칸의 아이템은 획득합니다.
5. 이동 결과는 서버가 계산합니다. 클라이언트는 방향만 보내고, 서버가 계산한 결과를 그대로 그립니다(서버 권한형).

**미정**
- 하루 이동 횟수 제한 여부와 횟수
- 점수·재화를 얻는 방식, 상점과 아이템 목록
- 플레이어끼리의 상호작용 규칙(밀기, 막기 등)
- 하루 단위 목표(데일리 챌린지)의 형태

## 블록

| 종류 | 동작 |
| --- | --- |
| 빈칸 | 그대로 지나갑니다. |
| 벽 | 부딪히면 앞 칸에서 멈춥니다. 겉모양(결정체, 덩굴, 얼음 등)은 달라도 충돌 동작은 같아서 하나의 종류로 다룹니다. |
| 긴 블록(2×1) | 두 칸을 차지하는 벽입니다. 왼쪽 칸과 오른쪽 칸을 따로 표시합니다. |
| 금 간 블록 | 부딪힐 때마다 내구도가 줄고, 0이 되면 부서져 길이 열립니다. |
| 거미줄 | 미끄러지던 플레이어를 붙잡아 그 칸 위에 세웁니다. |
| 색상 블록 | 플레이어가 움직일 수 있는 블록입니다. |

블록의 이름과 겉모양은 "다른 차원" 테마에 맞춰 바뀔 수 있습니다. 위 표는 동작 기준의 분류입니다.

## 공유 월드

- 맵은 하나이고 모든 플레이어가 함께 씁니다.
- 한 플레이어의 행동(블록 파괴, 블록 이동, 아이템 획득)은 같은 구역을 보고 있는 모든 플레이어 화면에 즉시 반영됩니다.
- 동시에 여러 이동 요청이 들어와도 결과가 엇갈리지 않도록, 서버는 이동을 **하나의 큐에서 순서대로** 처리합니다.
- 초기 개발에서는 맵을 고정해서 쓰고, 맵 자동 생성은 이후 과제로 둡니다.

## 맵 구조

맵은 **32×32칸 크기의 청크** 단위로 나누어 저장하고 전송합니다.

```
청크 하나 = 32 × 32 = 1024칸 = 1024바이트
인덱스    = y * 32 + x
```

각 칸은 **1바이트**입니다.

```
bit:  7 6 5 4 | 3 2 1 0
      종류      | 내부 값
     (4비트)    | (4비트)
```

- **블록 종류(상위 4비트)**: 빈칸, 벽, 긴 블록(왼쪽/오른쪽), 금 간 블록, 거미줄, 색상 블록 등 동작이 다른 종류만 구분합니다.
- **내부 값(하위 4비트)**: 종류마다 뜻이 다릅니다.
  - 벽: 겉모양 번호
  - 금 간 블록: 남은 내구도(1~15)
  - 색상 블록: 색 번호

이렇게 하면 청크 하나가 1KB로 작아서 저장과 전송이 가볍고, 충돌 계산은 상위 4비트만 보면 됩니다.
종류가 16개를 넘거나 내부 값이 더 필요해지면 칸당 2바이트로 늘리는 방안을 검토합니다(현재는 보류).

블록 종류 번호의 정확한 배정은 아직 확정하지 않았습니다.

## 실시간 동기화

- **클라이언트 → 서버**: 모든 요청은 HTTP(REST)로 보냅니다. 예: 이동 요청은 방향만 담아 보냅니다.
- **서버 → 클라이언트**: 맵 변화는 **SSE(Server-Sent Events)** 로 밀어 줍니다.
  - 클라이언트는 지금 보고 있는 주변 청크(최대 9개)를 구독합니다.
  - 이벤트 예시: 플레이어 이동, 블록 변경, 아이템 생성, 아이템 획득
  - 이벤트마다 증가하는 ID를 붙여, 연결이 끊겼다 다시 붙으면 놓친 이벤트부터 이어 받습니다. 너무 오래 끊겼으면 청크를 통째로 다시 받습니다.

브라우저에는 `EventSource`가 기본으로 있어서, 웹게임에서는 SSE를 별도 라이브러리 없이 쓸 수 있습니다.

## 배경

이 게임 규칙은 원래 팀 모바일 앱 프로젝트를 위해 기획했던 것입니다.
팀 프로젝트의 규칙이 바뀌면서, 기존 규칙을 개인 프로젝트인 웹게임으로 따로 이어서 만들고 있습니다.
